# go-atomos Framework Guide

## Concepts

go-atomos is an **actor-model framework** for Go. Every piece of application logic runs inside an *actor* — a single-goroutine entity that processes messages serially. This eliminates data races on actor state without locks in user code.

### Hierarchy

```
Cosmos (cluster)
 └── Node (process)
      └── Element (actor class — like a blueprint)
           └── Atom (actor instance — like an object)
```

- **Cosmos** — a cluster of nodes, identified by name. One etcd cluster = one Cosmos.
- **Node** — one process inside a Cosmos. Each node has a unique name.
- **Element** — a registered type of actor. Think of it as a class: it defines what messages an actor can handle and acts as a container/manager for Atom instances.
- **Atom** — a named instance of an Element. Each Atom has its own mailbox goroutine and isolated state.
- **ID** — a handle/reference to any actor (Cosmos, Element, or Atom). Like a file descriptor.

### How Messages Work

Each Atom has a **mailbox** — a linked-list queue processed by a single dedicated goroutine. When you send a message to an Atom, it's pushed onto that queue and processed serially. The sender blocks (sync) or gets a callback (async), but **inside the Atom there is never concurrent access to its state**.

### Lifecycle

```
Spawning ──→ Waiting ──→ Busy ──→ Waiting ──→ ... ──→ Stopping ──→ Halt
```

An Atom is `Spawning` while its constructor and data loader run, `Waiting` when idle, `Busy` while processing a message, and `Stopping` during shutdown. After `Halt` it is removed.

## Getting Started

### Project Structure

```
myapp/
├── main.go              # entry point
├── config.yaml           # node configuration
├── elements/
│   └── player.go         # your Element + Atom implementation
├── api/
│   ├── player.proto      # protobuf message definitions
│   ├── player.pb.go      # generated
│   └── player_atomos.pb.go  # generated by protoc-gen-go-atomos
└── go.mod
```

### Step 1: Define Your Messages (protobuf)

```protobuf
// api/player.proto
syntax = "proto3";
package player;

message LoginRequest  { string player_id = 1; }
message LoginResponse { string session_token = 2; }
message PlayerState   { int32 level = 1; int32 gold = 2; }
```

Run `protoc` with `protoc-gen-go-atomos` to generate the handler stubs.

### Step 2: Implement the Actor

```go
// elements/player.go
package elements

import (
    "myapp/api"
    "github.com/hwangtou/go-atomos"
)

// PlayerElement implements atomos.ElementDeveloper
type PlayerElement struct{}

func (p *PlayerElement) ElementConstructor() atomos.Atomos {
    return &PlayerElementActor{}
}

func (p *PlayerElement) AtomConstructor(name string) atomos.Atomos {
    return &PlayerAtomActor{playerID: name}
}

// ━━━ Element Actor ━━━

type PlayerElementActor struct{}

func (a *PlayerElementActor) String() string { return "PlayerElement" }

func (a *PlayerElementActor) Halt(from atomos.ID, cancelled []uint64) (bool, proto.Message) {
    return false, nil // Element has no persistent state in this example
}

// ━━━ Atom Actor ━━━

type PlayerAtomActor struct {
    playerID string
    level    int32
    gold     int32
}

func (a *PlayerAtomActor) String() string { return a.playerID }

func (a *PlayerAtomActor) Halt(from atomos.ID, cancelled []uint64) (bool, proto.Message) {
    // Return true + state to persist this Atom's data
    return true, &api.PlayerState{Level: a.level, Gold: a.gold}
}
```

### Step 3: Implement Message Handlers

```go
// Message handler signature (generated code calls these):
//   func(from atomos.ID, to atomos.Atomos, in proto.Message) (proto.Message, *atomos.Error)

func (a *PlayerAtomActor) HandleLogin(
    self atomos.AtomSelfID,
    from atomos.ID,
    in *api.LoginRequest,
) (*api.LoginResponse, *atomos.Error) {

    self.Log().Info("Player %s logging in", a.playerID)

    // Do your logic here — no concurrency concerns within this actor.

    return &api.LoginResponse{SessionToken: generateToken()}, nil
}
```

### Step 4: Write the Main Script

```go
// main.go
package main

import (
    "myapp/elements"
    "github.com/hwangtou/go-atomos"
)

type MyMainScript struct{}

func (s *MyMainScript) OnBoot(p *atomos.CosmosProcess) *atomos.Error {
    p.Self().Log().Info("Boot: setting up...")
    return nil
}

func (s *MyMainScript) OnStartUp(p *atomos.CosmosProcess) *atomos.Error {
    // Spawn initial atoms after all elements are ready.
    _, tracker, err := p.Self().CosmosSpawnAtom(
        p.Self(), "Player", "player-001", nil,
    )
    if err != nil {
        return err
    }
    defer tracker.Release() // always release trackers
    return nil
}

func (s *MyMainScript) OnShutdown() *atomos.Error {
    return nil
}

func main() {
    impl := atomos.NewImplementationFromDeveloper(&elements.PlayerElement{})

    runnable := &atomos.CosmosRunnable{}
    runnable.
        SetMainScript(&MyMainScript{}).
        AddElementImplementation(impl, true) // true = auto-spawn at startup

    atomos.Main(*runnable)
}
```

### Step 5: Configuration

```yaml
# config.yaml
cosmos: game-world
node: server-1

log-path: ./log
run-path: ./run
etc-path: ./etc

  - Player
```

```bash
go run main.go --config config.yaml
```

## Sending Messages

### Sync (Request-Reply)

Caller blocks until the target actor processes the message and returns a reply.

```go
resp, err := targetID.SyncMessagingByName(
    callerID,          // who is calling
    "Login",           // message name
    &api.LoginRequest{PlayerId: "bob"},
    nil,               // optional ArgsForBaseAtomos (timeout, etc.)
)
if err != nil {
    // handle error
}
loginResp := resp.(*api.LoginResponse)
```

### Async (Fire-and-Forget with Callback)

Caller does not block. The callback runs on the *caller's* mailbox goroutine when the reply arrives.

```go
err := targetID.AsyncMessagingByName(
    callerID, "Login", &api.LoginRequest{PlayerId: "bob"},
    func(reply proto.Message, err *atomos.Error) {
        if err != nil {
            self.Log().Error("Login failed: %v", err)
            return
        }
        loginResp := reply.(*api.LoginResponse)
        // handle success
    },
    nil,
)
if err != nil {
    // the push itself failed (actor not running, etc.)
}
```

### Message Arguments

Pass optional behavior flags via `ArgsForBaseAtomos`:

```go
// With timeout (for sync calls):
resp, err := targetID.SyncMessagingByName(caller, "Login", in,
    []atomos.ArgsForBaseAtomos{
        atomos.ArgBaseAtomosTimeout(5 * time.Second),
    },
)

// Prioritize this message (append to head of queue):
resp, err := targetID.SyncMessagingByName(caller, "Login", in,
    []atomos.ArgsForBaseAtomos{
        atomos.ArgBaseAtomosAppendToHead(),
    },
)

// Wait for the actor to be fully killed:
err := targetID.Kill(caller,
    []atomos.ArgsForBaseAtomos{
        atomos.ArgBaseAtomosWaitKilled(),
    },
)
```

## Getting References (IDs)

```go
// Get an Element by name
elemID, err := self.CosmosMain().CosmosGetElementID("Player")

// Get an existing Atom (or auto-spawn if persistence is configured)
atomID, tracker, err := self.CosmosMain().CosmosGetAtomID("Player", "player-001")
defer tracker.Release() // must release when done

// Spawn a new Atom
atomID, tracker, err := self.CosmosMain().CosmosSpawnAtom(
    self, "Player", "player-002", &api.PlayerState{Level: 1},
)
defer tracker.Release()
```

### IDTracker — Why and How

Each `CosmosGetAtomID` / `CosmosSpawnAtom` returns an `*IDTracker` alongside the `ID`. The tracker is a **reference count**: as long as any tracker exists for an Atom, the framework won't garbage-collect it. Always `defer tracker.Release()` when you're done.

Without releasing, halted Atoms accumulate in memory and are never cleaned up.

### CosmosGetAtomID vs CosmosSpawnAtom

| | `CosmosGetAtomID` | `CosmosSpawnAtom` |
|---|---|---|
| Atom exists | Returns it | Returns `ErrAtomSpawningAnExistedAtom` |
| Atom doesn't exist | Auto-spawns if `AutoData` is configured | Spawns it |
| Requires arg | No | Yes (can be nil) |

## Automatic Data Persistence

Implement `AutoData` on your `ElementDeveloper` to have the framework automatically save/load state.

```go
type PlayerElement struct {
    db *sql.DB
}

// Implement AutoData
func (p *PlayerElement) AtomAutoData() atomos.AtomAutoData {
    return p // PlayerElement itself handles Atom persistence
}

func (p *PlayerElement) ElementAutoData() atomos.ElementAutoData {
    return nil // no Element-level state
}

func (p *PlayerElement) GetAtomData(name string) (proto.Message, *atomos.Error) {
    var state api.PlayerState
    row := p.db.QueryRow("SELECT level, gold FROM players WHERE id = $1", name)
    if err := row.Scan(&state.Level, &state.Gold); err == sql.ErrNoRows {
        return nil, nil // first spawn — no previous state
    }
    return &state, nil
}

func (p *PlayerElement) SetAtomData(name string, data proto.Message) *atomos.Error {
    state := data.(*api.PlayerState)
    _, err := p.db.Exec(
        "INSERT INTO players (id, level, gold) VALUES ($1,$2,$3) ON CONFLICT(id) DO UPDATE SET level=$2, gold=$3",
        name, state.Level, state.Gold,
    )
    if err != nil {
        return atomos.NewErrorf(atomos.ErrFrameworkInternalError, "db: %v", err)
    }
    return nil
}
```

### How It Works

1. **GetAtomID("Player", "bob")** — Atom doesn't exist → calls `GetAtomData("bob")` → if data found, spawns Atom with that state.
2. **KillSelf() or Kill()** — `Halt()` returns `save=true` + state → `SetAtomData("bob", state)` is called.
3. **Element-level persistence** works the same way via `ElementAutoData`.

## Lifecycle Interface Reference

### Required Interfaces

| Interface | Method | When Called |
|-----------|--------|-------------|
| `Atomos` | `String() string` | Logging, debugging |
| `Atomos` | `Halt(from ID, cancelled []uint64) (save bool, data proto.Message)` | Atom is being killed |
| `ElementDeveloper` | `ElementConstructor() Atomos` | Element spawns |
| `ElementDeveloper` | `AtomConstructor(name string) Atomos` | Each Atom spawn |

### Optional Interfaces

All implementable on your `ElementDeveloper`:

| Interface | Purpose |
|-----------|---------|
| `AutoData` | Automatic state persistence (see above) |
| `ElementLoader` | Load/unload external resources (DB conns, file handles) |
| `ElementStartRunning` | Background goroutine launched at Element spawn |
| `ElementAtomExit` | Control Atom kill timeout (`StopTimeout`) and stagger (`StopGap`) |
| `ElementAuthorization` | Gate cross-actor kill operations (`AtomCanKill`) |
| `ElementVersion` | Hot-upgrade compatibility version (uint64, not semver) |
| `ElementAtomInitNum` | Pre-size Atom container map |
| `ElementLogLevel` | Per-Element log level override |
| `AtomosAcceptWormhole` | Receive wormhole messages |
| `AtomosRecover` | Custom panic recovery handlers |

## Task Scheduling

Every actor has a `Task()` scheduler for deferred and recurring work. Tasks execute on the actor's mailbox goroutine — no concurrency concerns.

```go
// Run once, immediately
self.Task().Add(func(taskID uint64) {
    self.Log().Info("Cleanup running")
})

// Run after a delay
self.Task().AddAfter(30*time.Second, func(taskID uint64) {
    self.Log().Info("Timeout check")
})

// Run on a cron schedule
entryID, _ := self.Task().AddCrontab("0 */6 * * *", func(taskID uint64) {
    self.Log().Info("Every 6 hours")
})
// self.Task().CancelCrontab(entryID)

// Cancel a task
taskID, _ := self.Task().AddAfter(60*time.Second, func(id uint64) {
    // won't run if cancelled
})
self.Task().Cancel(taskID)
```

### Named Queues

For work that should be serialized separately or mark-aware:

```go
// Serial queue — tasks in the same queue run in order
cancel, _ := self.Task().AddToSerialQueue("db-writes",
    func(taskID uint64) func() {
        // do work
        return nil // optional callback to run on the Atom's mailbox
    },
)

// Concurrent queue — each task gets its own goroutine
cancel, _ := self.Task().AddToConcurrentQueue(
    func(taskID uint64) func() {
        // CPU-heavy work
        return nil
    },
)

// Cancel the queued task
cancel("no longer needed")

// Check for a marked task
if self.Task().HasMarking("health-check") {
    // already scheduled
}
```

Task arguments:

```go
self.Task().AddToAtomosQueue(fn,
    atomos.ArgTaskMark("my-cleanup"),           // mark for HasMarking
    atomos.ArgTaskDelay(5*time.Second),         // delay before execution
    atomos.ArgTaskCancelCallback(func(reason string) {
        self.Log().Info("Task cancelled: %s", reason)
    }),
    atomos.ArgTaskRecoverFunc(func(r any) {
        self.Log().Error("Task panicked: %v", r)
    }),
)
```

## Wormholes

Wormholes carry arbitrary typed data between actors, bypassing the normal proto-message dispatch.

### Define a Wormhole Type

```go
type ReloadConfig struct {
    NewLogLevel atomos.LogLevel
}

func (ReloadConfig) IsWormhole() {} // implements BaseAtomosWormhole
```

### Send a Wormhole

```go
err := targetID.SendWormhole(callerID, ReloadConfig{NewLogLevel: atomos.LogLevel_Debug}, nil)
```

### Receive a Wormhole

Implement `AtomosAcceptWormhole` on your actor:

```go
func (a *PlayerAtomActor) AcceptWormhole(fromID atomos.ID, wormhole atomos.BaseAtomosWormhole) *atomos.Error {
    switch w := wormhole.(type) {
    case ReloadConfig:
        a.logLevel = w.NewLogLevel
        return nil
    default:
        return atomos.NewError(atomos.ErrAtomosNotSupportWormhole, "unknown wormhole type")
    }
}
```

## Hooks and Observability

`CosmosRunnable` exposes lifecycle hooks for monitoring and debugging:

```go
runnable.
    SetSpawningHook(func(id *atomos.IDInfo) {
        metrics.ActorSpawning.Inc()
    }).
    SetSpawnHook(func(id *atomos.IDInfo) {
        log.Printf("Actor spawned: %s", id.Info())
    }).
    SetStoppingHook(func(id *atomos.IDInfo) {
        log.Printf("Actor stopping: %s", id.Info())
    }).
    SetHaltedHook(func(id *atomos.IDInfo, err *atomos.Error, mt *atomos.AtomosMessageTrackerExporter) {
        log.Printf("Actor halted: %s (spawn=%v, stop=%v)", id.Info(), mt.Spawning, mt.Stopping)
        for _, m := range mt.Messages {
            log.Printf("  %s: count=%d max=%v avg=%v", m.Message, m.Count, m.Max, m.Average)
        }
    }).
    SetMessageTimeoutHook(func(id *atomos.IDInfo, timeout time.Duration, message string, args proto.Message) {
        log.Printf("Message timeout: %s %s after %v", id.Info(), message, timeout)
    }).
    SetRecoverHook(func(id *atomos.IDInfo, err *atomos.Error) {
        sentry.CaptureException(err)
    })
```

## Error Handling

All framework errors use the `*Error` type, which carries a stack trace.

```go
// Creating errors
return atomos.NewError(atomos.ErrAtomosInvalidArguments, "invalid input")
return atomos.NewErrorf(atomos.ErrAtomNotExists, "Atom %s not found", name)

// Adding context
if err != nil {
    return err.AddStack(self) // appends current file:line to the stack
}

// Panic recovery
// If you implement AtomosRecover, you receive structured panic info:
func (a *PlayerAtomActor) MessageRecover(name string, arg proto.Message, err *atomos.Error) {
    // err contains the panic stack — log, alert, or degrade gracefully
}
```

### Common Error Codes

| Code | Meaning |
|------|---------|
| `ErrAtomosIsNotRunning` | Target actor is halted |
| `ErrAtomosIsStopping` | Target actor is shutting down |
| `ErrAtomNotExists` | Atom name not found |
| `ErrAtomSpawningAnExistedAtom` | Tried to spawn a running Atom |
| `ErrAtomMessageHandlerNotExists` | No handler registered for that message name |
| `ErrAtomosNotSupportWormhole` | Target doesn't implement wormhole reception |
| `ErrFrameworkRecoverFromPanic` | A panic was caught by the framework |

## Clustering

### Overview

Multiple `go-atomos` processes can form a cluster coordinated via etcd. Each node registers itself in etcd and discovers peers via gRPC.

### Enable Clustering

```yaml
# config.yaml
enable-cluster:
  enable: true
  etcd-endpoints:
    - etcd-0.etcd:2379
    - etcd-1.etcd:2379
  optional-ports:
    - 50051
```

### Routing

By default, `CosmosGetElementID` / `CosmosGetAtomID` route to the local node. To route to remote nodes, implement a `CosmosMainGlobalRouter`:

```go
type MyRouter struct{}

func (r *MyRouter) GetCosmosNodeName(selfNode, element, atom string) (string, bool) {
    // Hash the atom name to a node
    nodes := []string{"node-1", "node-2", "node-3"}
    h := fnv.New32a()
    h.Write([]byte(atom))
    return nodes[h.Sum32()%uint32(len(nodes))], true
}

runnable.SetRouter(&MyRouter{})
```

### Cross-Node Messaging

Once routing is configured, messages are transparent:

```go
// This may go to a remote node if the router says so.
// The framework handles gRPC serialization automatically.
resp, err := self.CosmosMain().CosmosGetAtomID("Player", "bob")
resp, err := bobAtom.SyncMessagingByName(self, "Greet", &Greeting{Msg: "hello"}, nil)
```

## Logging

Actors log through their `SelfID`:

```go
self.Log().Debug("Processing message: %s", msgName)
self.Log().Info("Player %s connected", playerID)
self.Log().Warn("Slow query detected: %v", duration)
self.Log().Error("Failed to save: %v", err)
self.Log().Fatal("Unrecoverable: %v", err) // terminates the process
```

Log levels can be set per-process (config) or per-Element (`ElementLogLevel` interface).

## Parallel and Background Work

The `Parallel()` method spawns a goroutine protected by panic recovery:

```go
self.Parallel(func() {
    // Safe to do I/O or CPU work here without blocking the mailbox.
    // But do NOT access actor state — this runs on a different goroutine.
    result := expensiveComputation()
    // To safely update state, send a message back to yourself:
    self.SyncMessagingByName(self, "UpdateResult", result, nil)
})
```

## Testing

Use `MainForTest` to run the framework in-process:

```go
func TestMyElement(t *testing.T) {
    impl := atomos.NewImplementationFromDeveloper(&MyElement{})
    // ... wire up runnable ...

    atomos.MainForTest(*runnable, t)

    p := atomos.SharedCosmosProcess()
    _, tracker, err := p.Self().CosmosSpawnAtom(p.Self(), "MyElement", "test-1", nil)
    require.NoError(t, err)
    defer tracker.Release()

    // Test your actor
    resp, err := atomID.SyncMessagingByName(...)
    require.NoError(t, err)
}
```
